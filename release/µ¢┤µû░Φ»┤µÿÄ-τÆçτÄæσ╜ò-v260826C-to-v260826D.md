# 《璇玑录》v260826D 更新说明

> **发布版本**：v260826D（UTC+8）  
> **内部版本**：0.1.13  
> **升级来源**：仅限 v260826C（内部版本 0.1.12）  
> **发布形式**：Windows x64 严格相邻补丁，不含完整安装包。

## 修复：生图成功但界面显示破损图标

本轮检查确认，生图请求、Base64／URL 响应解析、图片落盘和图库索引保存属于不同链路。你能够在软件目录下找到生成图片，说明模型交互和本地归档大概率已经成功；问题集中在前端通过 Tauri `asset` 协议读取本地绝对路径时的显示链路，而不是图片模型本身。

此前界面仅尝试将本地图片路径转换为 `asset` URL；一旦 WebView 对路径编码、目录作用域或某一类图片格式的读取失败，`<img>` 会直接触发错误并显示破损图标。此次修复保留原有 `asset` 协议作为首选读取方式，并新增两层兼容保护：

1. 扩大 `data/images` 的 asset 协议路径匹配范围，兼容目录末级与按月份建立的嵌套图片目录。
2. 当 asset URL 加载失败时，前端会调用一个受限的后端读取命令。该命令先 canonicalize 校验图片必须存在且必须位于本地 `data/images` 目录，再根据文件魔数识别 PNG、JPEG、WebP、GIF、BMP 或 AVIF，并仅将该单一图片转换为 `data:` URL 返回界面显示。

该回退机制应用于占问完成页、星语图库的缩略图与大图、星语档案详情的关联图片。因此，旧版已成功归档但此前显示为破损图标的图片，也会在 D 版再次访问时尝试以安全回退方式显示。

> 本次修复不会改写图片文件名、图片内容、数据库记录或图库文件夹。若某个文件实际已被手动移动、删除或损坏，应用会显示“本地图片不可读取”，而不会绕过目录限制读取任意路径。

## 安装方法

1. 完全退出《璇玑录》。
2. 确认侧栏显示 **v260826C · UTC+8**，且 Windows“应用和功能”中的内部版本为 **0.1.12**。
3. 运行 `璇玑录-v260826C-to-v260826D-Patch.exe`。
4. 安装成功后重启软件，侧栏应显示 **v260826D · UTC+8**。
5. 进入星语图库，先查看此前破损图标对应的旧图片，再新生成一张图片进行验证。

补丁会备份当前主程序并在写入失败时尝试回滚。用户档案、SQLite 数据库、本地图片、备份、Profile 和 Windows Credential Manager 凭据均不会被修改。
