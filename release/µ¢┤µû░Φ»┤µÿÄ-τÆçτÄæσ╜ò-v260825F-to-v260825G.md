# 《璇玑录》v260825F → v260825G 数据迁移更新说明

**发布形式：** Windows x64 逐级数据迁移补丁

> 本补丁只适用于已安装 **v260825F** 的用户。安装前请完全退出《璇玑录》。如当前仍为 v260825E 或更早版本，请先按已有逐级补丁升级至 v260825F。

| 密钥 | API 密钥不在 SQLite 或图片文件夹中，仍由 Windows Credential Manager 管理；本次不会迁移或导出密钥。 |

## 为什么此前仍会报“Not allowed to open path”

此前仅授予了 `open_path` 命令本身，但该命令还要求一个**允许的文件路径范围**。因此，即使命令可调用，`C:\Users\…\XuanjiLu\images\…` 仍会被路径作用域拒绝。

v260825G 的直接修复是为安装目录下 `data\images\**\*` 添加显式路径范围；数据目录迁移让图片存储位置与该受控范围保持一致。换言之，**迁移本身不是唯一原因，显式路径权限才是解决“打开原图”报错的关键；两者组合后实现了更稳定且更窄的权限边界。**

## 数据迁移与保护机制

默认安装路径和旧数据路径都在 `%LOCALAPPDATA%` 同一磁盘卷上。补丁在确认 v260825F 主程序存在后执行以下顺序：

1. 备份 v260825F 主程序。
2. 若旧数据根存在、且安装目录下尚无非空 `data` 目录，则将整个 `%LOCALAPPDATA%\XuanjiLu` 目录重命名为软件目录下的 `data`。这会同时带走 SQLite、图库和备份目录，不会按图片逐张复制。
3. 写入 v260825G 主程序，并将安装版本更新为 0.1.6。
4. v260825G 首次启动时，自动把数据库中旧图片绝对路径前缀改为新数据根路径，因此已有档案和图库仍能找到对应图片。

> 如主程序写入失败，补丁会恢复 v260825F 主程序；若本次已移动数据目录，也会尝试将 `data` 目录重命名回旧位置。若安装目录中已存在非空 `data` 文件夹，补丁绝不覆盖它；应用首次启动会在新目录缺少数据库时从旧目录进行兼容复制，并在复制成功前保留旧数据。

## 安装步骤

1. 完全退出《璇玑录》，并确认任务栏通知区域没有残留进程。
2. 确认当前侧栏版本为 **v260825F · UTC+8**。
3. 运行 `璇玑录-v260825F-to-v260825G-Patch.exe`。
4. 等待补丁显示完成。首次启动 G 时，不要在数据库或图片目录上进行手工移动、重命名或删除操作。
5. 启动软件，确认侧栏版本为 **v260825G · UTC+8**；进入工作室偏好时，数据目录应显示在软件安装目录下的 `data` 文件夹。
6. 在星语图库中打开任意已归档的本地图片，确认“打开原图”可调起 Windows 默认图片查看器。
