# 《璇玑录》v260825I → v260825J 修复说明

**发布日期：** 2026-08-26（UTC+8）  
**升级路径：** v260825I（内部版本 0.1.8）→ v260825J（内部版本 0.1.9）  
**发布形式：** Windows x64 逐级修复补丁

> 本补丁仅适用于已安装 **v260825I** 的用户。安装前请完全退出《璇玑录》。

## 修复一：初始化参数解码失败

此前初始化按钮可能仍显示以下错误：

```text
invalid args `options` for command `initialize_archive`:
invalid type: map, expected a boolean
```

本版不再让 Tauri IPC 直接反序列化嵌套布尔对象。界面会把初始化选项序列化为**单一 JSON 字符串参数** `requestJson`，后端再显式解析该字符串为删除图片与删除 Profile 两个布尔选项。该方式避免了命令参数映射把对象误当作布尔值的歧义。

```json
{
  "requestJson": "{\"deleteImages\":true,\"deleteProfiles\":false}"
}
```

初始化的确认流程和清理范围保持不变。

## 修复二：打开原图的 ACL 拒绝

此前图库中的“打开原图”直接从前端调用系统查看器，仍可能遭到 opener 插件 ACL 的路径作用域拒绝。

本版改为：前端只请求应用后端的 `open_local_image` 命令；后端先对图片路径执行规范化校验，确认它是应用 `data\images` 专用目录内存在的文件，再由后端调用 Windows 系统默认图片查看器。前端不再拥有直接打开本地路径的权限。

| 项目 | v260825J 行为 |
| --- | --- |
| 图片路径 | 只允许应用本地 `data\images` 目录内的现存文件。 |
| 路径规范化 | 通过 canonical path 校验，拒绝目录外路径与不存在的文件。 |
| 系统查看器 | 仅由受控后端调用，不经过前端 opener ACL。 |
| HTTP 旧图片 | 仍由默认浏览器打开。 |
| data URI 旧图片 | 仍提示其未归档为本地文件，不能调用系统查看器。 |
